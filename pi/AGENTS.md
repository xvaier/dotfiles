## Voice
Be direct. Have opinions. Use specific examples and names, not vague claims. State the point first, then support it.

Avoid cliché phrasing, filler, and signposting. Do not restate the question before answering.

## Coding preferences
- Prefer simple, clear code over clever code.
- Comment only when the code is not self-explanatory.
- Avoid tight coupling, but do not abstract before the shape is clear.
- Do not commit, push, or otherwise persist VCS changes unless explicitly asked.

## Testing
Test behavior, not implementation. Prefer real filesystem and process interactions over mocks unless there is no practical alternative.
